WHAT IT IS

z-ai-spend-auditor is a TEE-resident AI-spend auditor built on the Terminal 3 ADK. Teams can't honestly answer "what did AI cost us this month?" — this contract turns usage events into an append-only, tenant-private ledger inside the enclave, with per-provider monthly totals, budget + spike alerts, and SHA-256 audit receipts folded into the transaction claims digest (offline-verifiable via the host Merkle receipt).

Base tenant world only: zero outbound HTTP, zero third-party keys, nothing leaves the enclave.


WHAT IT DOES

- Append-only usage ledger in tenant-private KV maps (contract-only ACLs, no tenant override)
- Monthly per-provider aggregates: calls, tokens in/out, micro-USD integer cost (no float drift); month rollover is a key prefix, no setup step to forget
- Budget + spend-spike alerts exposed as queryable data (not notifications to lose)
- SHA-256 receipts sealed into the tx claims digest — every record is audit-verifiable offline
- Providers are data, not code: any AI provider works day one (openai, anthropic, anything)


HOW IT USES THE T3N ADK

- Quickstart auth flow: T3nClient + handshake + authenticate, tenantDid read back from the session
- TenantClient for contract registration and four private KV maps (usage / agg / alerts / budget) with explicit contract-only ACLs on both writer and reader sides
- Control-plane map-entry-set for the budget seed
- executeAndDecode for every contract call
- ERC-8004 agent card hosting via the t3n CLI (register-agent script)
- Capabilities come straight from the WIT world: kv-store + logging + tenant-context, nothing else

BUGS FACED (full write-ups with repro: docs/BUG_REPORTS.md in the repo)

1. Testnet DKG fleet incident: handshake failed 0/3 quotes valid (RTMR3 all-zero on all 3 peers) while the signed trust manifest was frozen — platform-side, healed 2026-09-15 04:23Z (manifest v1789446184). Affects every participant; worth a fleet health probe endpoint.
2. kv_store::set_claims_digest requires the RAW 32-byte digest; passing the 64-char hex string only fails at tx time ("claims digest must be exactly 32 bytes") — cargo test on pure helpers cannot catch host-boundary type errors.
3. Contract re-publish allocates a NEW numeric contract_id (0.1.0→1023, 0.1.1→1024, 0.1.2→1025) although docs describe the id as stable.
4. After any re-publish, map ACLs still point at the OLD contract id → "access denied: TenantContract(...) cannot write map" — writer AND reader grants must both be re-granted.
5. No RPC reads a contract's numeric id back (listDetailed has no id field) — persist it at register time or burn a version bump to rediscover it.
6. Obfuscated SDK ships as a single-line esm.js printing ~2.4 MB of noise around real errors; subprocess PIPE capture truncates stderr at exactly 65536 bytes and the error line is lost — always capture stderr to a file.
7. Docs/SDK mismatches: node emits lowercase "map already exists" (docs show camelCase MapAlreadyExists); maps.delete is async and slow (>5 min) requiring poll-and-retry.
